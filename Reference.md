## Options

Options are plain variables on the `Importer.gd` instance. Set them before calling an import method;
they stay in effect for all following imports done with that instance.

```gdscript
var importer = preload("res://runtime/Importer.gd").new()
importer.add_id_as_metadata = true
var map = importer.import("res://maps/level1.tmx")
```

### use_default_filter

Type `bool`, default: `false`

To ensure that looks are the same as in Tiled, all layer texture filters are set to "nearest".
Setting this option to `true` leaves all texture filters as they are by default ('inherited').

### add_class_as_metadata

Type `bool`, default: `true`

If enabled the content of the Tiled class field is added as metadata `class` to the corresponding Godot node
(objects, and layers of every kind; a layer without a class gets none).
Independent of this option tiles always get their class as metadata `class` on their TileData, and the class of a
tileset is stored as metadata `class` on the generated TileSet (as all tilesets of a map end up in one Godot TileSet,
the last tileset with a class wins).

### add_id_as_metadata

Type `bool`, default: `false`

If enabled the Tiled object id is added as metadata `id` to the corresponding Godot element.

### no_alternative_tiles

Type `bool`, default: `true`

If enabled flipped/rotated tiles are not created as alternative tiles; the engine's transform flags
of the cell are used instead. This is faster and keeps the TileSet small.
Set it to `false` to get the alternative tiles (with flipped collision polygons) of earlier versions.
*Please note: Rotated non-square tiles may appear wrongly placed if this option is `true`.
This currently can't be avoided due to Godot specifics.*

### map_wangset_to_terrain

Type `bool`, default: `false`

Switch on the 'old' (prior to upstream version 1.4.0) mapping where Tiled wangsets ('terrain sets') were mapped to
Godot terrains to keep the terrain set names.

### custom_data_prefix

Type `String`, default: `"data_"`

Tile properties with this prefix on the name are (after removing the prefix) explicitly assigned to Godot's tile
custom data for special purposes in Godot.
Tile properties without this prefix on the name are assigned to the tile's meta data.
This allows for distinguishing between custom data and (more general) meta data.
With an empty prefix every tile property becomes custom data.

### save_tileset_to

Type `String`, default: `""` (don't save)

Every map generated by the importer gets a Godot TileSet. If a resource path (e.g. `user://level1_tileset.tres`) is set,
this TileSet is saved there so that it can be used otherwise.

### parallax_mode

Type `String`, default: `"parallax2d"`

How layers with a parallax factor (`parallaxx` / `parallaxy`) are created.

- `"parallax2d"`: the layer's node stays at its place in the layer hierarchy, wrapped in a `Parallax2D`
  named `<layer name> (PX)`, so the offsets, opacity, tint and visibility of its groups apply and the
  draw order is Tiled's (a foreground factor > 1 draws in front). `scroll_scale` is the parallax factor
  (1.0 for an axis that is not set); in a group that has a factor itself it is chosen so that the layer
  scrolls with the product of the factors, as in Tiled. `scroll_offset` is
  `parallax origin * (1 - scroll_scale)` (the map's `parallaxoriginx` / `parallaxoriginy`): Tiled moves a
  layer by `(1 - factor) * (view centre + origin)`, a Parallax2D by `(1 - scroll_scale) * screen_offset`
  plus its `scroll_offset`, and `screen_offset` is the screen's **top-left corner**; so the layer is where
  Tiled shows it when the view centre is at the same point. To match Tiled for a viewport of size `v`, add
  `v / 2 * (1 - scroll_scale)` to `scroll_offset`. An image layer with `repeatx` / `repeaty` gets
  `repeat_size` = the image size on that axis and `repeat_times = 2`. The map's background colour stays a
  direct child of the root.
- `"legacy"`: as before 3.1: every parallax layer is moved into one `ParallaxBackground` (`<map name> (PBG)`,
  a CanvasLayer at layer -100) as a `ParallaxLayer` (`<layer name> (PL)`, deprecated since Godot 4.3) with
  `motion_scale` = the factor and `motion_mirroring` for repeated image layers; the background colour moves
  in with the first one. Group offsets and opacity do not reach these layers, the parallax origin is ignored.

Layers of class `parallax` are a `Parallax2D` themselves in both modes; in `"parallax2d"` mode they get the
same scroll scale, origin and repeat, and an object or group layer's offset goes into `scroll_offset`
(a Parallax2D overwrites its `position`).

### animation_mode

Type `String`, default: `"strip"`

How Tiled tile animations are created. Godot animates a tile through the atlas cells that follow it
(in a row or a column, at equal steps), always starting with the tile itself; Tiled allows any tiles in
any order.

- `"strip"`: every animated tile gets an atlas source of its own holding its frames side by side in the
  animation's order (composed from the tileset image(s) when the map is imported; repeats, other rows and
  image collection tiles of equal size are fine), with one tile animated over them using the frame durations.
  That tile carries all data of the animated tile (collision, navigation and occlusion polygons, custom data,
  metadata, terrain, texture origin, material, probability), and every cell or tile object of the animated
  tile uses it. The strip sources get the source ids after those of the tilesets. The tileset's own atlas is
  left without animations, so the frame tiles can be placed on their own.
- `"atlas"`: as before 3.1, the animation is set on the tile in the tileset's atlas. Only animations whose
  frames start with the tile and follow it at equal steps in a row or column, with room for all of them, can
  be shown; any other animation is skipped as a whole with a warning. An animation that does not start with
  the tile itself, and any animation of an image collection tile, falls back to a strip (with a warning).

In both modes a tile object of an animated tile becomes an `AnimatedSprite2D` (one looping animation
`"default"`, autoplay, a frame per animation frame with its duration) instead of a `Sprite2D`, unless the
object has the `clip_artifacts` property (which needs a Sprite2D region; a warning is printed).

### unknown_class_fallback

Type `String`, default: `"staticbody"`

What a Tiled object becomes whose class (or `godot_node_type`) is not one of the classes of the
[mapping table](#mapping-from-tiled-elements-to-godot-elements), e.g. a rectangle of class `Door`:

- `"staticbody"` (the default, as before): a StaticBody2D with the object's collision shape, i.e. a solid wall.
- any other class of the mapping table (`"area"`, `"characterbody"`, `"rigidbody"`, `"animatablebody"`,
  `"navigation"`, `"occluder"`, `"polygon"`, `"line"`, `"path"`; `""` treats the object as one without a class):
  the node that class gives.
- `"node2d"`: a plain Node2D at the object's position and rotation. Metadata `shape` holds the shape in the
  object's coordinates (a `Rect2` from `(0, 0)` for a rectangle, and the bounds of an ellipse or capsule; a
  `PackedVector2Array` for a polygon or polyline), `size` the object's `Vector2(width, height)`; class, id and
  properties are applied as on any node. A tile object stays a Sprite2D (with a body only if its tile's class
  asks for one), a point a Marker2D, a text a Label.

`"instance"` and `"parallax"` are not accepted (a warning, then `"staticbody"`).
Each unknown class is reported once per import with a warning, whatever `add_class_as_metadata` says.

### Tiled project file

Not an option variable but the optional last parameter of the import methods:
pass the Tiled project file (.tiled-project) to enable the use of Tiled's Custom Types.
Members of a custom class that are not overridden on an element are added with their default values.

### Post processor

Use `import_with_post_processing` / `import_from_zip_with_post_processing` to manipulate the generated map by a
post processor script. The script must extend `Node` and have a method `_post_process` that receives the root node
of the generated map and returns the (changed) node. The script is loaded with `load()`, i.e. it has to be a project
resource (it is not read from a zip archive).

Mini Example (manipulating the Material setting on element with name 'Area2'):

```gdscript
extends Node

func _post_process(base_node: Node):
	var area = base_node.find_child("Area2")
	var mat = CanvasItemMaterial.new()
	mat.blend_mode = CanvasItemMaterial.BLEND_MODE_MUL
	area.material = mat
	return base_node
```

### Import result

After each import `last_error_count` and `last_warning_count` on the importer instance hold the number of errors and
warnings reported during that import (see [Runtime document](Runtime.md#result)).

**New since version 1.5.0:**  Mapping can alternatively be controlled by a custom property 'godot_node_type'.<br>
Probably this new way is preferable if you want to keep open the use of Tiled's Custom Types.

Tile collision elements are controlled by custom properties of type 'int'.  
Property value is the assigned layer number.

**Names:** The Tiled element name entry is mapped to the Godot element name.  
If the Tiled name entry is empty a default Godot element name is created to avoid cryptic looking names.

## Custom properties reference

Setting these properties affect the Godot settings accordingly.  
Custom properties which are not in this list or not fitting to the element are added as Meta Data.  
Their values are typed as in Tiled: `bool`, `int`, `float`, `string`, `file` (a path String), `color` (a `Color`;
a String `#RRGGBBAA` before version 3.1), `object` (see below), `class` (a Dictionary) and `list` (an Array).  
If assigned to a tile and the property name is starting with the custom data prefix they are added to the Tile Custom Data.

> **Tile** custom properties: The property name and type will refer to a layer in the Godot TileSets's Custom Data Layer array,   
the property value is assigend to the tile's Custom Data entry which conists only of the layer number and the value.  
**New since version 2.1.0 / 1.7.0:** Only properties with custom data prefix on the name  are handled this way

New since v1.5.4: A special custom property `godot_group` to specify the Godot Group to which the imported element is assigned.  
You can assign more than one group by passing the group names as a comma-separated list.

New since v1.6.0: You can download [this file](./supplemental/godot_enums.json) containing several Godot enums and import it using the Custom Type Editor

New since v1.6.6: A special custom property `godot_script` to specify a node script.  

New since v1.6.8: A special custom property `godot_atlas_id` to force special atlas id values.  
The property is either a tileset property or in case of an image collection tileset a tile property.  
**Please use this property only if you know what you're doing and why!** 

Remarks:  
- (*) refers to a string consisting of comma separated values, each value representing an element number to enable.  
Example for a collision layer property (name+value), where layers 1,3,5,6,7 on physics layer 0 are to enable:  
`collision_layer_0 = 1,3,5-7` (you can set ranges like 5-7 in this example)
- (col) refers to a property of type `color` (Tiled's colour picker; Tiled saves it as `#AARRGGBB`, alpha first,
and it is read that way) or of type `string`, read as Godot reads a colour: `#RRGGBB`, `#RRGGBBAA` (alpha last)
or a colour name. Example: `#4e4aff`
- (enum) refers to an int, value can be taken from the list

Properties with "n is layer number": if number appendix is missing, layer 0 is assumed  
i.e. "collision_layer" is equivalent to "collision_layer_0"

Properties of type 'file' refer to previously saved Godot resources e.g. 'material' or a script file.  
By specifing the property and setting its value to the resource file path the resource will be loaded.  
**Please note:** The numerous resource-specific properties, e.g. for materials, can only be set by loading previously saved resources.  
This seems to be convenient as providing all of these properties would greatly inflate the already extensive list.

## Specialities

- For some custom properties e.g. 'use_parent_material' there's a catch that this can be ambiguous.  
`Example: A rectangle with class 'staticbody' is mapped to a StaticBody2D (parent) + a CollisionShape2D (child).`  
`Both elements do have a 'use_parent_material' property. Which one of them should the property affect?`  
By default the property affects the parent.  
If you want the property to affect the child, prefix the name with two underscores e.g. '__use_parent_material'
- If linear texture filters are in effect, on tile objects (which are mapped to a Sprite2D) it may happen that the sprite shows artifacts on the border.  
This can be overcome by adding a special property to the object named 'clip_artifacts' and setting it to `On`.
- Skip Tiled layers by adding a custom property 'no_import' (type bool) and set it to 'true' (new in v1.2).  

## Newly supported Tiled features

Supported by this runtime fork in addition to upstream YATI 2.2.x:

| Tiled feature | Godot result |
|---------------|--------------|
| Object layer `draworder` | `topdown` (Tiled's default) sets `y_sort_enabled` on the object layer node; `index` keeps the object order |
| Layer blend mode (`mode`) `add` / `multiply` | `CanvasItemMaterial` with `BLEND_MODE_ADD` / `BLEND_MODE_MUL` on the layer node (other modes: see below) |
| Object opacity | `modulate.a` of the created node(s) |
| Text object bold / italic | `SystemFont` with `font_weight = 700` / `font_italic = true` |
| Class-typed properties (nested properties) | Metadata (and tile custom data) of type `Dictionary` `{member_name: value}`, nested classes as nested Dictionaries - same for .tmx and .tmj |
| Layer parallax factor inside groups, map parallax origin (`parallaxoriginx` / `parallaxoriginy`) | A `Parallax2D` wrapping the layer at its place in the hierarchy, `scroll_offset` from the origin (see [parallax_mode](#parallax_mode)) |
| Image layer `repeatx` / `repeaty` on a plain (non-parallax) image layer | `TextureRect` with `STRETCH_TILE` and texture repeat, extended over the map area on the repeated axis |
| Tile animations of any frame sequence (frames not starting with the tile, ping-pong, other rows, image collections) | A strip atlas per animated tile ([animation_mode](#animation_mode)) |
| Tile objects of animated tiles | `AnimatedSprite2D` |
| Object references (`object` properties) to objects inside group layers | Resolved like references to top-level objects |
| Deprecated XML tile layer data (`<tile gid="..."/>` children, no encoding) | Imported like CSV data |
| Tileset class | Metadata `class` on the generated TileSet |

## Tiled features not supported

These Tiled features have no Godot equivalent and are ignored:

- `map.renderorder` (Godot always renders in its own order)
- Oblique orientation (`skewx` / `skewy`)
- `hexsidelength` of hexagonal maps (Godot derives the hexagon from the tile size)
- `tileset.tilerendersize` and `tileset.fillmode`
- Tileset `<transformations>` (allowed flips/rotations are only an editor setting)
- `wangcolor.probability` and properties on wangsets / wangcolors
- Layer blend modes other than `normal`, `add` and `multiply` (a warning is printed and the mode is ignored)
- Text object `underline`, `strikeout` and `kerning` (Label has no such switches)
- The hexagonal 120° rotation flag (gid bit 28, masked off)
- Embedded images (`<image>` with a `<data>` child instead of a `source`)
