## Options

Options are plain variables on the `Importer.gd` instance. Set them before calling an import method;
they stay in effect for all following imports done with that instance.

```gdscript
var importer = preload("res://runtime/Importer.gd").new()
importer.add_id_as_metadata = true
var map = importer.import("res://maps/level1.tmx")
```

### use_default_filter

Type `bool`, default: `false`

To ensure that looks are the same as in Tiled, all layer texture filters are set to "nearest".
Setting this option to `true` leaves all texture filters as they are by default ('inherited').

### add_class_as_metadata

Type `bool`, default: `true`

If enabled the content of the Tiled class field is added as metadata `class` to the corresponding Godot node
(objects, and layers of every kind; a layer without a class gets none).
Independent of this option tiles always get their class as metadata `class` on their TileData, and the class of a
tileset is stored as metadata `class` on the generated TileSet (as all tilesets of a map end up in one Godot TileSet,
the last tileset with a class wins).

### add_id_as_metadata

Type `bool`, default: `false`

If enabled the Tiled object id is added as metadata `id` to the corresponding Godot element.

### no_alternative_tiles

Type `bool`, default: `true`

If enabled flipped/rotated tiles are not created as alternative tiles; the engine's transform flags
of the cell are used instead. This is faster and keeps the TileSet small.
Set it to `false` to get the alternative tiles (with flipped collision polygons) of earlier versions.
*Please note: Rotated non-square tiles may appear wrongly placed if this option is `true`.
This currently can't be avoided due to Godot specifics.*

### map_wangset_to_terrain

Type `bool`, default: `false`

Switch on the 'old' (prior to upstream version 1.4.0) mapping where Tiled wangsets ('terrain sets') were mapped to
Godot terrains to keep the terrain set names.

### custom_data_prefix

Type `String`, default: `"data_"`

Tile properties with this prefix on the name are (after removing the prefix) explicitly assigned to Godot's tile
custom data for special purposes in Godot.
Tile properties without this prefix on the name are assigned to the tile's meta data.
This allows for distinguishing between custom data and (more general) meta data.
With an empty prefix every tile property becomes custom data.

### save_tileset_to

Type `String`, default: `""` (don't save)

Every map generated by the importer gets a Godot TileSet. If a resource path (e.g. `user://level1_tileset.tres`) is set,
this TileSet is saved there so that it can be used otherwise.

### parallax_mode

Type `String`, default: `"parallax2d"`

How layers with a parallax factor (`parallaxx` / `parallaxy`) are created.

- `"parallax2d"`: the layer's node stays at its place in the layer hierarchy, wrapped in a `Parallax2D`
  named `<layer name> (PX)`, so the offsets, opacity, tint and visibility of its groups apply and the
  draw order is Tiled's (a foreground factor > 1 draws in front). `scroll_scale` is the parallax factor
  (1.0 for an axis that is not set); in a group that has a factor itself it is chosen so that the layer
  scrolls with the product of the factors, as in Tiled. `scroll_offset` is
  `parallax origin * (1 - scroll_scale)` (the map's `parallaxoriginx` / `parallaxoriginy`): Tiled moves a
  layer by `(1 - factor) * (view centre + origin)`, a Parallax2D by `(1 - scroll_scale) * screen_offset`
  plus its `scroll_offset`, and `screen_offset` is the screen's **top-left corner**; so the layer is where
  Tiled shows it when the view centre is at the same point. To match Tiled for a viewport of size `v`, add
  `v / 2 * (1 - scroll_scale)` to `scroll_offset`. An image layer with `repeatx` / `repeaty` gets
  `repeat_size` = the image size on that axis and `repeat_times = 2`. The map's background colour stays a
  direct child of the root.
- `"legacy"`: as before 3.1: every parallax layer is moved into one `ParallaxBackground` (`<map name> (PBG)`,
  a CanvasLayer at layer -100) as a `ParallaxLayer` (`<layer name> (PL)`, deprecated since Godot 4.3) with
  `motion_scale` = the factor and `motion_mirroring` for repeated image layers; the background colour moves
  in with the first one. Group offsets and opacity do not reach these layers, the parallax origin is ignored.

Layers of class `parallax` are a `Parallax2D` themselves in both modes; in `"parallax2d"` mode they get the
same scroll scale, origin and repeat, and an object or group layer's offset goes into `scroll_offset`
(a Parallax2D overwrites its `position`).

### animation_mode

Type `String`, default: `"strip"`

How Tiled tile animations are created. Godot animates a tile through the atlas cells that follow it
(in a row or a column, at equal steps), always starting with the tile itself; Tiled allows any tiles in
any order.

- `"strip"`: every animated tile gets an atlas source of its own holding its frames side by side in the
  animation's order (composed from the tileset image(s) when the map is imported; repeats, other rows and
  image collection tiles of equal size are fine), with one tile animated over them using the frame durations.
  That tile carries all data of the animated tile (collision, navigation and occlusion polygons, custom data,
  metadata, terrain, texture origin, material, probability), and every cell or tile object of the animated
  tile uses it. The strip sources get the source ids after those of the tilesets. The tileset's own atlas is
  left without animations, so the frame tiles can be placed on their own.
- `"atlas"`: as before 3.1, the animation is set on the tile in the tileset's atlas. Only animations whose
  frames start with the tile and follow it at equal steps in a row or column, with room for all of them, can
  be shown; any other animation is skipped as a whole with a warning. An animation that does not start with
  the tile itself, and any animation of an image collection tile, falls back to a strip (with a warning).

In both modes a tile object of an animated tile becomes an `AnimatedSprite2D` (one looping animation
`"default"`, autoplay, a frame per animation frame with its duration) instead of a `Sprite2D`, unless the
object has the `clip_artifacts` property (which needs a Sprite2D region; a warning is printed).

### always_wrap_root

Type `bool`, default: `false`

The root of the imported tree is a `Node2D` named after the map file, holding the layers and the map's
properties. A map with a single layer (and no background colour) returns that layer's node instead, renamed
after the map, and the map's properties are applied to it after the layer's own (a map property wins over a
layer property of the same name). With this option on, such a map is wrapped like any other: the root is a
`Node2D` with the map's properties, the layer its child with its own name and properties. Recommended for new
code, so that the root's type does not depend on the number of layers; it is planned to become the default in 4.0.

### unknown_class_fallback

Type `String`, default: `"staticbody"`

What a Tiled object becomes whose class (or `godot_node_type`) is not one of the classes of the
[mapping table](#mapping-from-tiled-elements-to-godot-elements), e.g. a rectangle of class `Door`:

- `"staticbody"` (the default, as before): a StaticBody2D with the object's collision shape, i.e. a solid wall.
- any other class of the mapping table (`"area"`, `"characterbody"`, `"rigidbody"`, `"animatablebody"`,
  `"navigation"`, `"occluder"`, `"polygon"`, `"line"`, `"path"`; `""` treats the object as one without a class):
  the node that class gives.
- `"node2d"`: a plain Node2D at the object's position and rotation. Metadata `shape` holds the shape in the
  object's coordinates (a `Rect2` from `(0, 0)` for a rectangle, and the bounds of an ellipse or capsule; a
  `PackedVector2Array` for a polygon or polyline), `size` the object's `Vector2(width, height)`; class, id and
  properties are applied as on any node. A tile object stays a Sprite2D (with a body only if its tile's class
  asks for one), a point a Marker2D, a text a Label.

`"instance"` and `"parallax"` are not accepted (a warning, then `"staticbody"`).
Each unknown class is reported once per import with a warning, whatever `add_class_as_metadata` says.

### object_refs

Type `String`, default: `"nodepath"`

What a property of type `object` (a reference to another object of the map) becomes:

- `"nodepath"` (the default): a `NodePath` from the node holding the property to the node created for the
  target object, or the target node itself for a Node-typed property of that name; see
  [Object references](#object-references).
- `"geometry"`: the target object's geometry in map coordinates, as before 3.1: a `PackedVector2Array` for a
  polygon, polyline or (rotated) rectangle, a `Vector2` for a point, the id as a String for an ellipse, capsule,
  tile object or an id no object has.
- `"both"`: the `NodePath` as in `"nodepath"`, and the geometry as in `"geometry"` as metadata `<name>_shape`.

### class_scenes

Type `Dictionary`, default: `{}`

Tiled class name (compared case-insensitively) → scene path, e.g. `{"Enemy": "res://enemies/enemy.tscn"}`.
Objects and tile objects of that class become instances of the scene, like class `instance` with a `res_path`,
without a property on every object. A relative path is relative to the map. See
[Scene mapping and node properties](#scene-mapping-and-node-properties).

### read_godot_scene_from_custom_types

Type `bool`, default: `true`

With a [project file](#tiled-project-file): a custom class type with a member `godot_scene` (type `file`) maps its
objects (scope `object`) and tiles (scope `tile`) to that scene, as `class_scenes` does. The member's value is
relative to the project file; an object that overrides it saves its own value, relative to the map (or the
template). The `godot_scene` property itself is not stored as metadata. Off: `godot_scene` is an ordinary property.

### assign_node_properties

Type `bool`, default: `true`

A custom property that no special case of the [custom properties reference](#custom-properties-reference) handles
and whose name is a property of the created node (an `@export var` or any `var` of its script, or an engine
property such as `rotation`) is assigned to that property with `set()` instead of becoming metadata, converted to
the property's type where that is safe; a value that does not fit stays metadata, with a warning. Off: every such
property is metadata, as before 3.1. See [Scene mapping and node properties](#scene-mapping-and-node-properties).

### Tiled project file

Not an option variable but the optional last parameter of the import methods:
pass the Tiled project file (.tiled-project) to enable the use of Tiled's Custom Types.
Members of a custom class that are not overridden on an element are added with their default values.

### Post processor

Use `import_with_post_processing` / `import_from_zip_with_post_processing` to manipulate the generated map by a
post processor script. The script must extend `Node` and have a method `_post_process` that receives the root node
of the generated map and returns the (changed) node. The script is loaded with `load()`, i.e. it has to be a project
resource (it is not read from a zip archive).

Mini Example (manipulating the Material setting on element with name 'Area2'):

```gdscript
extends Node

func _post_process(base_node: Node):
	var area = base_node.find_child("Area2")
	var mat = CanvasItemMaterial.new()
	mat.blend_mode = CanvasItemMaterial.BLEND_MODE_MUL
	area.material = mat
	return base_node
```

### Import result

After each import `last_error_count` and `last_warning_count` on the importer instance hold the number of errors and
warnings reported during that import (see [Runtime document](Runtime.md#result)).

**New since version 1.5.0:**  Mapping can alternatively be controlled by a custom property 'godot_node_type'.<br>
Probably this new way is preferable if you want to keep open the use of Tiled's Custom Types.

Tile collision elements are controlled by custom properties of type 'int'.  
Property value is the assigned layer number.

**Names:** The Tiled element name entry is mapped to the Godot element name.  
If the Tiled name entry is empty a default Godot element name is created to avoid cryptic looking names.

## Custom properties reference

Setting these properties affect the Godot settings accordingly.  
Custom properties which are not in this list or not fitting to the element are added as Meta Data, unless the
node has a property of that name ([assign_node_properties](#assign_node_properties)).  
Their values are typed as in Tiled: `bool`, `int`, `float`, `string`, `file` (a path String), `color` (a `Color`;
a String `#RRGGBBAA` before version 3.1), `object` (a `NodePath`, see [Object references](#object-references)), `class` (a Dictionary) and `list` (an Array).  
If assigned to a tile and the property name is starting with the custom data prefix they are added to the Tile Custom Data.

> **Tile** custom properties: The property name and type will refer to a layer in the Godot TileSets's Custom Data Layer array,   
the property value is assigend to the tile's Custom Data entry which conists only of the layer number and the value.  
**New since version 2.1.0 / 1.7.0:** Only properties with custom data prefix on the name  are handled this way

New since v1.5.4: A special custom property `godot_group` to specify the Godot Group to which the imported element is assigned.  
You can assign more than one group by passing the group names as a comma-separated list.

New since v1.6.0: You can download [this file](./supplemental/godot_enums.json) containing several Godot enums and import it using the Custom Type Editor

New since v1.6.6: A special custom property `godot_script` to specify a node script.  

New since v1.6.8: A special custom property `godot_atlas_id` to force special atlas id values.  
The property is either a tileset property or in case of an image collection tileset a tile property.  
**Please use this property only if you know what you're doing and why!** 

Remarks:  
- (*) refers to a string consisting of comma separated values, each value representing an element number to enable.  
Example for a collision layer property (name+value), where layers 1,3,5,6,7 on physics layer 0 are to enable:  
`collision_layer_0 = 1,3,5-7` (you can set ranges like 5-7 in this example)  
New in 3.1: such a mask property may also be of type `int`, the bitmask itself (bit 0 is layer 1; a Tiled enum with
"Allow multiple values (flags)" and storage type `int` saves exactly that), or a `string` property of a flags enum of the
[project file](#tiled-project-file) stored as string (`Player,Enemy`): each value's index in the enum is its bit, so an
enum `World, Player, Enemy, Pickup` maps `Player,Enemy` to layers 2 and 3. Without the project file such names set no
layer. Names that are not values of the enum are ignored with a warning.
- (col) refers to a property of type `color` (Tiled's colour picker; Tiled saves it as `#AARRGGBB`, alpha first,
and it is read that way) or of type `string`, read as Godot reads a colour: `#RRGGBB`, `#RRGGBBAA` (alpha last)
or a colour name. Example: `#4e4aff`
- (enum) refers to an int, value can be taken from the list

Properties with "n is layer number": if number appendix is missing, layer 0 is assumed  
i.e. "collision_layer" is equivalent to "collision_layer_0"

Properties of type 'file' refer to previously saved Godot resources e.g. 'material' or a script file.  
By specifing the property and setting its value to the resource file path the resource will be loaded.  
A relative path is resolved like Tiled saves it: relative to the file that holds the property, i.e. the map, or the
template (.tx) for the properties of a template object; a property that a template instance overrides is saved in the
map and so is relative to the map.  
**Please note:** The numerous resource-specific properties, e.g. for materials, can only be set by loading previously saved resources.  
This seems to be convenient as providing all of these properties would greatly inflate the already extensive list.

## Scene mapping and node properties

An object can become an instance of a Godot scene without a `res_path` on each object: map its class to a scene.
For a Tiled object (or tile object) the importer decides in this order:

1. A `godot_node_type` property: the node type it names (as before).
2. [class_scenes](#class_scenes)`[class]` (case-insensitive): an instance of that scene.
3. A `godot_scene` (file) member of the object's custom class in the project file, if
   [read_godot_scene_from_custom_types](#read_godot_scene_from_custom_types) (the object's own `godot_scene`
   value when it overrides the member): an instance of that scene. The project's class names are case-sensitive,
   as in Tiled.
4. Class `instance` with a `res_path` property: an instance of that scene (as before).
5. The class mapping of the [mapping table](#mapping-from-tiled-elements-to-godot-elements).
6. [unknown_class_fallback](#unknown_class_fallback) for any other class.

For a tile object the object's own class is looked up first, then its tile's class (a `godot_scene` member of the
tile's class in scope `tile`, else `object`). A template instance is decided by its template's object, with the
instance's class if it sets one. Text objects stay Labels.

An instance keeps the object's name (else the scene file's name), position, rotation and visibility; a tile object's
instance also its size as `scale` and the `res_alignment` property. It gets the class as metadata and the object's
custom properties like any node.

**Node properties.** With [assign_node_properties](#assign_node_properties) (the default) a custom property whose
name is a property of the node is assigned to it: `hp` (int) of an object of class `Enemy` lands in the
scene's `@export var hp: int`, not in metadata. Property names are compared exactly (Godot's are case-sensitive);
the node's `name` and `script` are never set this way (use the object's name and `godot_script`). Conversions:

| Tiled type | Accepted for a property of type |
|------------|---------------------------------|
| `bool`, `string`, `float`, `color` | the same type (`bool`, `String`, `float`, `Color`) |
| `int` | `int`, `float`, an enum (the value) |
| `string` | `String`, `StringName`, `NodePath`, an enum (a constant's name, e.g. `ANGRY`; case, blanks and `_` ignored) |
| `file` | a Resource type (the file is loaded; it must be of that class), `String` (the path as saved) |
| `class` | `Dictionary` (`{member: value}`) |
| `list` | `Array`; a typed array (`Array[int]`, `Array[NodePath]`, ...) when every item fits |
| `object` | `NodePath`, a Node type, see [Object references](#object-references) |

An untyped `var` takes the value as metadata would hold it. A value that does not fit stays metadata, with a warning.

**Two passes.** `godot_script` is attached before any other property of the node is handled, so the script's
variables exist when they are assigned, whatever the order of the properties in Tiled.

**The `_tiled_import` hook.** When the map is built (all layers, object references resolved), every node created for
an object that has a method `_tiled_import(info: Dictionary)` (its scene's script, or one set by `godot_script`) gets
it called once, before the root is returned:

```gdscript
func _tiled_import(info: Dictionary) -> void:
	# info.id: int, info.name: String, info.class: String
	# info.properties: {name: value} - every custom property as the importer typed it
	#     (an object property a NodePath from this node, a list an Array, a class a Dictionary)
	# info.rect: Rect2(x, y, width, height) in map pixels, as Tiled saves it
	# info.shape: Rect2 from (0, 0), or a PackedVector2Array (polygon, polyline) in object coordinates
	# info.shape_type: "rectangle", "ellipse", "capsule", "point", "polygon", "polyline", "tile" or "text"
	max_hp = info.properties.get("hp", max_hp)
```

The node is not in the scene tree yet (`_ready` has not run); the hook sees the imported tree only.

## Object references

A custom property of type `object` names another object of the map by its id. With
[object_refs](#object_refs) `"nodepath"` (the default) or `"both"` it is resolved in a second pass, once every
layer is built, to the node created for that object:

- **Which node:** the node the object became: the collision object (StaticBody2D, Area2D, ...) of a shape
  object, not its CollisionShape2D; for a tile object the body when its tile has collision shapes, else its
  Sprite2D (or AnimatedSprite2D); an instantiated scene's root; the Marker2D, Label, Polygon2D, Line2D, Path2D,
  NavigationRegion2D or LightOccluder2D otherwise. Objects inside group layers and template instances work the
  same way.
- **What is set:** a `NodePath` from the node holding the property to the target node (`get_node(path)` finds it
  while both are in the imported tree, also after it is added to a scene). If the node has a property of the
  same name, it gets the value instead of the metadata: a `NodePath` property the path, a `Node`-typed property
  (e.g. `@export var target: Node2D`) the node itself, an untyped `var` the path. Otherwise the path is metadata
  of that name.
- **Lists:** a property of type `list` whose items are objects becomes an `Array[NodePath]`; a list mixing
  objects with other items an untyped Array with a `NodePath` for each object item. A property of the same
  name typed `Array[NodePath]` or `Array[Node]` (or a Node class) gets it as that array.
- **Unset or dangling:** an object property that is not set (id 0) or names an id no imported object has (a
  deleted object, one on a layer with `no_import`) gives an empty `NodePath()` and a warning.
- The map's own object properties resolve from the root node; on a single-layer map without
  `always_wrap_root` from the layer that is returned.

**References to objects of other maps.** Tiled's `object` properties only reach objects of the same map. For
a warp or door system name the other map by a convention: a custom class type (in the project file) with exactly
two members, `map` (type `file`) and `object` (type `int` or `object`). Such a class-typed property arrives as the
Dictionary `{"map": "<path as saved, relative to the map file>", "object": <id>}` like any class value and is
not resolved; the game resolves it when it needs to, e.g. by importing the other map (with `add_id_as_metadata`
on) and looking for the node with that `id` metadata. Join the `map` member with the directory of the map that
holds the property.

## World files and map bounds

**Map bounds.** The root node of every imported map (also a single layer returned as the root) has the metadata:

| Metadata | Type | Value |
|----------|------|-------|
| `map_rect` | `Rect2` | the map's bounds in pixels, in the root's coordinates |
| `map_size_tiles` | `Vector2i` | the map's size in tiles (an infinite map's: of the union of its chunks) |
| `tile_size` | `Vector2i` | the map's tile width and height |
| `orientation` | `String` | `orthogonal`, `isometric`, `staggered` or `hexagonal` |

`map_rect` is Tiled's map size: `(0, 0, width * tilewidth, height * tileheight)` for an orthogonal map; the bounding box
of the diamond for an isometric one, `(0, 0, (width + height) * tilewidth / 2, (width + height) * tileheight / 2)` (the
importer places the diamond's left corner at x = 0); Tiled's size of the staggered or hexagonal grid
(`hexsidelength` included). An infinite map's bounds are those of the union of the chunks of all its tile layers (in
tiles, then in pixels as above; negative coordinates included), `Rect2()` without chunks. Layer offsets are not
included. `TilemapCreator.get_map_rect()` returns the same after `create()`. A camera's limits, for example:

```gdscript
var r: Rect2 = map.get_meta("map_rect")
camera.limit_left = int(r.position.x); camera.limit_top = int(r.position.y)
camera.limit_right = int(r.end.x); camera.limit_bottom = int(r.end.y)
```

**World files.** `WorldLoader.gd` reads Tiled's `.world` files:

```gdscript
const WorldLoader = preload("res://runtime/WorldLoader.gd")
for entry in WorldLoader.parse("res://maps/overworld.world"):
	print(entry.path, " at ", entry.rect)   # String, Rect2i in pixels
```

- `maps` entries: `fileName` (relative to the world file) and `x`, `y`, `width`, `height` as written.
- `patterns` entries: every `.tmx` / `.tmj` file directly in the world file's directory (not in subdirectories) whose
  name matches `regexp` (searched, not anchored, as Tiled does) and that is not listed under `maps`; captures 1 and 2
  are the x and y indices: position `(x * multiplierX + offsetX, y * multiplierY + offsetY)`, size `mapWidth` /
  `mapHeight` when the pattern has them, else the map's own size in pixels (`map_rect`, read from the map file once
  and cached; `WorldLoader.clear_cache()` forgets it). A file matching several patterns takes the first.
- The result lists the `maps` entries in their order, then the pattern matches sorted by file name.
- `onlyShowAdjacentMaps` is an editor setting and ignored.
- `WorldLoader.parse(world_file, zip_file)` reads the world file, its directory and the maps from a zip archive
  (paths inside it).

`Importer.import_world(world_file, project_file = "")` imports every map and returns a `Node2D` named after the world
file with each map's root as a child at its `rect.position` (the importer's options apply to each map;
`last_error_count` and `last_warning_count` add up all maps). It is meant for small worlds and tests: a world streamer
calls `WorldLoader.parse()` once and `import()` for the maps it needs.

## Specialities

- For some custom properties e.g. 'use_parent_material' there's a catch that this can be ambiguous.  
`Example: A rectangle with class 'staticbody' is mapped to a StaticBody2D (parent) + a CollisionShape2D (child).`  
`Both elements do have a 'use_parent_material' property. Which one of them should the property affect?`  
By default the property affects the parent.  
If you want the property to affect the child, prefix the name with two underscores e.g. '__use_parent_material'
The forwarding to children works for the collision objects (StaticBody2D, Area2D, CharacterBody2D, RigidBody2D,
AnimatableBody2D) only; on a NavigationRegion2D, LightOccluder2D or any other node a `__` property becomes metadata
of that name (with the underscores).
- If linear texture filters are in effect, on tile objects (which are mapped to a Sprite2D) it may happen that the sprite shows artifacts on the border.  
This can be overcome by adding a special property to the object named 'clip_artifacts' (type bool) and setting it to `On`
(the sprite region then shrinks by half a pixel on every side). An animated tile's object stays a Sprite2D with it.
- Skip Tiled layers by adding a custom property 'no_import' (type bool) and set it to 'true' (new in v1.2).

## Tiled features not supported

These Tiled features have no Godot equivalent and are ignored:

- `map.renderorder` (Godot always renders in its own order)
- Oblique orientation (`skewx` / `skewy`)
- `hexsidelength` of hexagonal maps (Godot derives the hexagon from the tile size)
- `tileset.tilerendersize` and `tileset.fillmode`
- Tileset `<transformations>` (allowed flips/rotations are only an editor setting)
- `wangcolor.probability` and properties on wangsets / wangcolors
- Layer blend modes other than `normal`, `add` and `multiply` (a warning is printed and the mode is ignored)

- Embedded images (`<image>` with a `<data>` child instead of a `source`)
